# Безопасность

## Что открывает приложение

Для управления системной точкой доступа приложение запускает helper от имени shell (UID 2000). Helper вызывает `ITetheringConnector.startTethering` / `stopTethering`.

Helper:

- слушает только `127.0.0.1`;
- принимает только запросы с случайным токеном;
- не принимает соединения из сети;
- не использует root;
- не использует Shizuku.

## Отладка по USB

Пока USB-отладка включена, любой авторизованный USB-хост получает shell-доступ к телефону.

Рекомендации:

- не подключайте телефон к незнакомым компьютерам и зарядным станциям с передачей данных;
- используйте charge-only кабель/порт, если не нужен ADB-хост;
- периодически отзывайте авторизации ADB в настройках разработчика;
- не оставляйте телефон без присмотра с включённой отладкой и подключённым кабелем.

## Отладка по Wi-Fi

Wi-Fi-отладка дополнительно открывает adbd в сети:

- порт анонсируется через mDNS;
- подключиться может только хост с сохранённым ключом;
- новый хост требует 6-значный код сопряжения.

Риски:

- устройства в той же Wi-Fi-сети видят ADB-сервис;
- заражённый компьютер с сохранённым ADB-ключом получает shell;
- общественные и гостевые Wi-Fi повышают риск.

Рекомендации:

- включайте Wi-Fi-отладку только на доверенной сети и только на время запуска/перезапуска helper;
- после запуска helper выключайте её;
- не сопрягайте незнакомые устройства;
- не показывайте код сопряжения;
- отзывайте авторизации ADB, если устройство больше не используется.

## Почему без отладки нельзя

Android не разрешает обычному приложению вызывать `TetheringManager.startTethering`: требуется `TETHER_PRIVILEGED` (`signature|privileged`). Выдать это разрешение через `pm grant` нельзя.

Helper запускается через adbd и живёт в cgroup adbd-сессии. Поэтому:

- Wi-Fi-отладка нужна для запуска helper;
- USB-отладка нужна, чтобы Android не остановил helper;
- если выключить обе, helper остановится.

Это ограничение платформы, а не ошибка приложения.

## Альтернативы

- **Root-helper**: процесс запускается от root/system при загрузке и не зависит от adbd. Требует root/Magisk/KernelSU и повышает общий риск для устройства.
- **Privileged/system app**: подпись платформы или установка в `/system/priv-app`; требует кастомной прошивки.
- **Shizuku**: запускается через adb shell; не гарантирует выживание при полном отключении отладки и не решает проблему cgroup.

## Токен helper

Токен генерируется случайно и хранится в SharedPreferences приложения. Он не публикуется в интерфейсе и не логируется. Не передавайте токен третьим лицам и не публикуйте журналы с ним.

## Что не делает приложение

- не запрашивает root;
- не устанавливает сертификаты;
- не читает чужие приложения;
- не отправляет данные на серверы;
- не содержит аналитики и рекламы.

## Ответственное использование

Приложение предназначено для личного телефона и личной точки доступа. Не используйте его для обхода ограничений оператора или доступа к чужим устройствам.
